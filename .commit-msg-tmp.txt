R13 专项: 自动补全 × 中文输入法 —— 实测发现真问题并修复

发现:
- CodeMirror 的 autocompletion 在 view.composing === true 时**仍会**调用补全源
- 后果: 中文组词时补全弹窗与输入法候选词同屏, 互相抢回车/空格 ——
  这正是 Monaco #2199 那个开了多年没修的病的形态
- 修复前 1/5 通过 (核心用例: 组合期间弹了 2 次补全)

修复:
- 每个自定义补全源首行加 if (context.view?.composing) return null;
- 这条升级为编码规约, 已写入 README 硬约束表与计划 R13

修复后 5/5 通过, 关键平衡点:
- 用例 3: 非组合输入时补全照常弹出并可选 (没被废掉)
- 用例 4: 中文上屏后补全正常跟随 (组合期间 0 次)

同时修掉我自己在这次测试中的三个错误 (已写入结论文档):
- REPORT 变量名遮蔽导致脚本崩 (改为 REPORT_PATH / RESULTS)
- 一次 edit 吃掉换行, 把 buildDecorations 整个函数注释掉 -> Vite 500 白屏
  诊断方法: fetch('/src/main.js') 取 Vite 编译错误, 而不是在浏览器控制台里找
