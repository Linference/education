# R13 专项结论：自动补全 × 中文输入法（已解决）

> 测试时间：2026-10-01
> 测试方式：`poc/ime/cdp_r13_test.py`（Playwright + CDP `Input.imeSetComposition` 驱动真实组合输入）
> 涉及版本：`@codemirror/autocomplete` 6.20.3、`@codemirror/view` 6.43.13
> 结果：**5/5 通过**（修复前为 1/5）

---

## 一、为什么专门测这个

这是全项目**最高风险的技术未知**，三个理由：

1. 格致最核心的编辑体验就是「打 `[[` 补全笔记名」，而笔记名大多是**中文**；
2. Monaco 至今栽在这里 —— **#2199「Chinese IME does not work correctly with CompletionItemProvider」仍然是 open**，格致当初放弃 Monaco 就有这条；
3. 之前的 IME PoC 为了测「纯净」的输入法行为，**刻意关掉了补全** —— 这一层完全没验过。

---

## 二、实测发现的真问题

**CodeMirror 的 `autocompletion` 在 `view.composing === true` 时，仍会调用补全源。**

证据（修复前的测试输出）：

```
[FAIL] 组合输入期间补全弹窗出现了 2 次
    组合中 view.composing: True        ← CodeMirror 自己知道在组词
    组合期间弹窗次数: 2                 ← 但补全照样弹
    上屏后补全总弹出次数: 1
```

也就是说：中文输入法正在组词（候选词列表开着）时，补全弹窗也会在同一位置弹出，两者**都在监听回车/空格/方向键**，互相抢按键。这正是 Monaco #2199 那个病的形态。

> 注意这不等于「CodeMirror 有 bug」——它提供了 `view.composing` 这个判断依据，只是**默认不会**替你在自定义补全源里拦截。这是使用者的责任，而文档没有把这个坑说得很重。

---

## 三、修复方式

在**每一个自定义补全源**的第一行加拦截：

```js
function wikilinkSource(context) {
  if (context.view?.composing) return null;   // ★ 组合期间绝不触发
  ...
}

function tagSource(context) {
  if (context.view?.composing) return null;   // ★ 同上
  ...
}
```

两处都必须加。**新写任何补全源时，第一行就要写这个判断** —— 这是本项目的一条规定，不是可选优化。

## 四、修复前后对照（同一套用例）

| # | 用例 | 修复前 | 修复后 |
| --- | --- | --- | --- |
| 1 | **组合输入期间补全不弹出（核心）** | ✖ 弹了 **2 次** | ✔ **0 次** |
| 2 | 组词途中按回车/空格不误插入补全项 | ✔ 0 次 | ✔ 0 次 |
| 3 | 非组合输入时补全正常工作 | ✔ 选中「情态笔记」 | ✔ 仍正常 |
| 4 | 中文上屏后补全的跟随 | ✖ 组合期间弹了 1 次 | ✔ 上屏后弹窗正常打开，组合期间 0 次 |

**用例 3 和 4 是这次修复的关键平衡点**：不能为了躲开 IME 就把补全废掉。
- 用例 3 证明：普通键入时补全照常弹出、能选中
- 用例 4 证明：中文上屏**之后**补全仍会正常弹出（`上屏后弹窗打开: True`）

## 五、这次测试暴露的我自己的三个错误（写给后来者）

### 1. 断言探针词与初始文档冲突（第二次犯）

上一轮 IME 测试我用「测试」当探针，而初始文档里本来就有「测试」于是误报。这次我用了生僻字 `龘`，没有重犯 —— 但值得记：**探针词必须先断言它不在初始文档里**。

### 2. 变量名遮蔽导致脚本崩

`REPORT` 既当「报告路径（字符串）」又当「结果列表」，`REPORT.append` 直接抛 `AttributeError`。已改为 `REPORT_PATH` 与 `RESULTS`。

### 3. 一次 edit 吃掉了换行，把整个函数注释掉了

我用编辑工具改注释时，替换文本少了一个换行，结果：

```js
// ------ 装饰（模拟 Live Preview 的真实压力面）function buildDecorations(view) {
```

**整个函数声明被注释掉**，后面的 `}` 变成野括号 → Vite 返回 500 → 页面白屏。

诊断路径值得记：浏览器只报 `Failed to load resource: 500`，看不到原因；用 `fetch('/src/main.js')` 取 Vite 的响应体才拿到真实错误（它把错误以 HTML 包着 JSON 返回）。**下一页白屏时，先问 Vite 要编译错误，别在浏览器控制台里找。**

## 六、对计划的影响

1. **R13 从"未验证风险"降级为"已验证并已解决"**，但修复方式本身升级为**编码规约**：所有补全源必须首行判 `view.composing`。
2. **补全与 IME 可以共存** —— 这是格致「Obsidian 级编辑体验」的技术前提，现在有证据了。
3. 测试脚本已固化为可复跑用例（`cdp_r13_test.py`），应纳入 CI：**每次升级 CodeMirror 相关包都要重跑**（`cdp_ime_final.py` + `cdp_r13_test.py` 两个套件）。
4. 仍需**真人手测**的部分：CDP 只能驱动 Blink 的组合输入路径，**测不到操作系统输入法引擎**（候选词翻页、双拼/注音/仓颉编码、以及真实输入法是否会把回车"吃掉"而不传给页面）。这一条保留在人工清单里（`测试清单.md` 的 D 组）。
